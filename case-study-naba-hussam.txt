**Project summary (3 sentences)**

**Clothie** is a custom full-stack fashion e-commerce platform built for **Naba Hussam**, a Pakistani women’s apparel brand. It unifies **ready-to-wear** and **made-to-order** commerce in one stack: React storefront and admin, Express API, MongoDB Atlas, and AWS S3, with **COD**, bank transfer, guest checkout, and region-aware shipping (Karachi vs outside). The repo shows production deployment (Docker, Nginx, separate storefront/admin domains), GA4/GTM tracking, a COD operations console, and a recent **sale/discount** system—documented in depth in `Clothie_PROJECT_DOCUMENTATION.md`, `PROJECT_ANALYSIS.md`, and `caseStudyData.json`.

### 2. Overview

**Challenge**

Naba Hussam needed more than a template shop: a single experience for **ready-to-wear** and **made-to-order** lines, with deposits, modification windows, and category-specific attributes—not a one-size-fits-all cart. The Pakistan market demanded **Cash on Delivery** and **bank transfer**, not card-only checkout, plus **guest checkout** so first-time buyers weren’t forced to register. Operations had to run on dynamic categories (e.g. Luxury Pret, Printed Coordes), Karachi vs outside-Karachi shipping, size charts, and reliable product imagery at scale—without a monolith that couldn’t evolve with the brand.

**Approach**

Tech-binaries delivered **Clothie**: three deployable surfaces—a customer **React + Vite** storefront, a dedicated **admin** app, and an **Express + MongoDB** API—containerized and fronted by **Nginx** with the API kept off the public internet. Product, cart, order, and settings domains share one data model but support **MTO vs RTW** flows, **COD management** (delivery assignment, attempts, analytics), and **S3-backed** media. We wired **GA4/GTM** e-commerce events and policy pages for trust, then shipped a **layered sale engine** (product, category, subcategory, and bulk product rules) with storefront badges and an admin sales overview—so merchandising doesn’t require developer deploys.

### 4. Process (5 chapters)

#### 01 — Discovery

- Mapped **RTW vs MTO** journeys: standard cart/checkout vs deposits, design categories, and bank-transfer-only rules for custom pieces.  
- Captured **Pakistan-specific** requirements: COD, bank transfer proof, within/outside Karachi delivery tiers, PKR pricing.  
- Defined **admin personas**: catalog managers, order ops, and settings owners (categories, size charts, bank details, home hero transitions).

#### 02 — Architecture

- Split **storefront**, **admin**, and **API** with REST resources (`/api/product`, `/cart`, `/order`, `/settings`) and JWT + admin middleware.  
- Chose **MongoDB Atlas** for flexible product/order schemas and **AWS S3** for images, size charts, and payment proofs (migrated from Cloudinary per git history).  
- Designed **guest orders** with email linking on registration and **Nginx** reverse proxy so HTTPS clients never hit a raw backend port.

#### 03 — Design & UX

- **Tailwind**-based responsive UI: product grid, slide-in cart drawer, collection filters by segment (RTW / MTO).  
- Product detail patterns: size selection, add-ons, size-chart modals, MTO attribute pickers, sale badges when `effectivePrice` differs from list price.  
- Admin UX: order status workflows, bulk actions, COD console, Settings hub including **Sales / Discount Management** and current-sales overview modal.

#### 04 — Engineering

- Implemented **18+ modules** (auth, catalog, cart, checkout, orders, COD analytics, settings, search, analytics, policies).  
- Integrated **GA4-compatible** `view_item`, `add_to_cart`, `begin_checkout`, `purchase` via dataLayer + gtag; Meta pixel hooks in frontend history.  
- Built **sale price resolver** (`salePriceResolver.js`, settings `sales` array) with admin modals for category/subcategory/product-level campaigns.

#### 05 — Launch

- **Docker** images to GHCR, `linux/amd64` builds, host ports 7000–7002 behind Nginx.  
- Production hostnames documented for storefront and admin (public brand domain; admin subdomain).  
- Hardening pass: **JWT/CORS** production fixes, auth troubleshooting docs, sitemap generation on frontend build.
